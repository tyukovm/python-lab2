## Описание работы

Цель работы — разработать простое веб-приложение на Python, сознательно внедрить в него минимум две уязвимости из списка OWASP Top 10, показать на практике, как эти уязвимости эксплуатируются, и продемонстрировать их исправление (патч).

В качестве приложения выбран небольшой **каталог товаров (мини-магазин)**:
- главная страница со списком товаров;
- поиск товаров по названию;
- страница отдельного товара с отзывами и возможностью оставить свой отзыв.

Приложение написано на Python с использованием фреймворка **Flask**, данные хранятся в базе **SQLite**. Запускается локально.

## Используемые технологии

### Flask

Flask — лёгкий веб-фреймворк для Python. Он берёт на себя приём HTTP-запросов от браузера и позволяет связывать адреса (маршруты) с функциями на Python, которые формируют ответ.

Основные элементы, используемые в приложении:
- `flask.Flask(__name__)` — создаёт объект приложения.
- `@app.route("/адрес")` — декоратор, связывающий указанный адрес (маршрут) с функцией, расположенной под ним: когда браузер запрашивает этот адрес, выполняется эта функция, а всё, что она возвращает, отправляется в браузер как содержимое страницы.
- `flask.request.args.get("имя")` — получение значения параметра, переданного в адресе после знака `?` (например, из `/search?q=слово` можно получить значение `слово`).
- `app.run(port=5001)` — запуск встроенного сервера разработки на указанном порту.

### SQLite

SQLite — встроенная в Python (модуль `sqlite3`) база данных, хранящаяся в одном файле (`shop.db`). Не требует установки отдельного сервера. Используется для хранения таблиц `products` (товары) и `reviews` (отзывы).

## Описание угроз (выбранные уязвимости OWASP Top 10)

### 1. SQL-инъекция (Injection)

Возникает, когда данные, введённые пользователем, подставляются в SQL-запрос напрямую, путём склеивания строк, без разделения «текста для поиска» и «кода команды». В результате пользователь может вписать часть SQL-синтаксиса (например, кавычку, оператор `OR`, комментарий `--`) и изменить смысл всего запроса — например, обойти условие поиска и получить все данные таблицы, которые не должны были быть доступны.

### 2. Межсайтовый скриптинг (Cross-Site Scripting, XSS)

Возникает, когда текст, введённый пользователем (например, текст отзыва), сохраняется и затем выводится на странице без обработки — то есть вставляется в HTML «как есть». Если пользователь вписывает в текст тег `<script>...</script>`, браузер любого человека, открывшего эту страницу, воспринимает его не как текст, а как код, и выполняет его. В данной работе уязвимость относится к **хранимому (persistent) XSS**: вредоносный код сохраняется в базе данных и выполняется у каждого, кто впоследствии откроет страницу товара.

## Пошаговое описание работы

### Шаг 1. Проектирование базы данных

Создан скрипт `init_db.py`, который формирует базу `shop.db` с двумя таблицами:

- **products** (`id INTEGER PRIMARY KEY`, `name TEXT`, `price INTEGER`) — товары каталога;
- **reviews** (`id INTEGER PRIMARY KEY`, `product_id INTEGER`, `text TEXT`) — отзывы, привязанные к товару через `product_id`.

Таблицы заполняются тестовыми данными: список товаров (наушники, планшет, плеер, мышка и др.) и несколько отзывов к ним.

### Шаг 2. Разработка приложения (`applab2.py`)

Реализованы три маршрута:

- **`/`** — выводит список всех товаров из таблицы `products`.
- **`/search?q=...`** — ищет товары, в названии которых встречается введённая пользователем подстрока (SQL-команда с `LIKE`).
- **`/product?id=...&review=...`** — показывает товар с указанным `id` и все отзывы к нему; если передан параметр `review`, добавляет его в таблицу `reviews` как новый отзыв.

### Шаг 3. Определение мест внедрения уязвимостей

Было решено внедрить:
1. SQL-инъекцию — в обработку поиска (`/search`) и в обработку параметра `id`/`review` в `/product`.
2. XSS — в вывод текста отзывов на странице `/product`.

### Шаг 4. Реализация уязвимостей

**SQL-инъекция.** Параметры запроса (`word`, `product_id`, `new_review`) склеивались с текстом SQL-запроса напрямую через оператор `+`, без разделения данных и команды:

```python
rows = shop.execute("SELECT name, price FROM products WHERE name LIKE '%" + word + "%'").fetchall()
```

**XSS.** Текст отзыва выводился на страницу без какой-либо обработки специальных символов:

```python
result = result + row[0] + "<br>"
```

### Шаг 5. Проверка (эксплуатация) уязвимостей

**Проверка вручную, через браузер:**
- SQL-инъекция: запрос `/search?q=x' OR 1=1 --` возвращал список всех товаров вместо пустого результата, хотя такого товара не существует.

Скрипт на Python с использованием библиотеки `requests` обращается к работающему приложению так же, как это делает браузер:

### Шаг 6. Исправление уязвимостей (патч)

**Исправление SQL-инъекции.** Запросы переписаны с использованием параметризованных запросов: вместо склейки строк в SQL-команде ставится символ-заглушка `?`, а значение передаётся отдельным аргументом. Библиотека `sqlite3` сама безопасно подставляет значение как данные, а не как часть команды:

```python
rows = shop.execute("SELECT name, price FROM products WHERE name LIKE ?", ("%" + word + "%",)).fetchall()
```

**Исправление XSS.** Перед выводом текста отзыва в HTML он пропускается через функцию `html.escape()`, которая заменяет специальные символы (`<`, `>` и др.) на их безопасные HTML-эквиваленты, из-за чего браузер отображает текст как есть, не выполняя его как код:

```python
result = result + html.escape(row[0]) + "<br>"
```
